# Native Windows updates

Researched 2026-11-11 against the current dirty working tree, including [CONTEXT](../../CONTEXT.md), [implementation plan](../implementation-plan.md), and the packaging sources below. Research only: no dependency, implementation, release, or Windows update acceptance was performed. Upstream snapshots: T3 Code `ea3e20a0e283ba3bf7c3d6004142d8f13b603319`; Velopack `92d6a1c91716729d449034df5c50307dcce39493`. Rust API documentation currently resolves to 1.2.161; pin and qualify matching SDK/CLI versions rather than assuming master and published documentation describe identical releases.

## Recommendation and repository privacy

**Implement a native Rust Velopack installer/update channel, with the existing portable EXE retained as a separate manual-download option.** Keep the source repository private if desired. Privacy does not prevent building the updater or testing it locally; it prevents anonymous clients from reading that repository's releases. GitHub requires repository read access, and its release API permits unauthenticated access only to public resources. [GitHub release access](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases), [release API](https://docs.github.com/en/rest/releases/releases#list-releases).

Choose either a separate public binary-release repository or an HTTPS feed on the existing distribution host. A public binary feed does not require publishing application source, but makes those binaries public. To retain admitted-user-only downloads, serve the feed and packages through authenticated endpoints/custom source; keep GitHub credentials on CI/server. Do not embed a shared PAT in the client or reuse invitation secrets as update URLs. Velopack supports authenticated GitHub sources, plain HTTP sources and custom sources; private GitHub downloads need a token. [Update sources](https://docs.velopack.io/integrating/update-sources), [Rust GithubSource](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/src/lib-rust/src/sources/github.rs).

Velopack's framework is MIT licensed, compatible with this application's MIT license; retain its copyright/permission notice and audit the pinned bundled helper/dependency notices. Hosted Flow is optional: self-hosting is documented. Existing GStreamer/CRT/media distribution obligations remain separate. [License](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/LICENSE), [distribution](https://docs.velopack.io/distributing/overview), [current runtime qualification](../../deploy/windows/portable-runtime.md).

## What T3 Code actually does

T3 Code is a UX/release reference, not a Rust updater dependency. Its [ElectronUpdater adapter](https://github.com/pingdotgg/t3code/blob/ea3e20a0e283ba3bf7c3d6004142d8f13b603319/apps/desktop/src/electron/ElectronUpdater.ts) wraps `electron-updater`; [DesktopUpdates](https://github.com/pingdotgg/t3code/blob/ea3e20a0e283ba3bf7c3d6004142d8f13b603319/apps/desktop/src/updates/DesktopUpdates.ts) explicitly disables automatic download and install-on-quit. The [sidebar update control](https://github.com/pingdotgg/t3code/blob/ea3e20a0e283ba3bf7c3d6004142d8f13b603319/apps/web/src/components/sidebar/SidebarUpdatePill.tsx) separates checking, downloading, progress and confirmed install, and presents release notes/errors. Borrow that state flow in egui, with a restart warning while publishing/watching; do not introduce Electron.

Its [artifact builder](https://github.com/pingdotgg/t3code/blob/ea3e20a0e283ba3bf7c3d6004142d8f13b603319/scripts/build-desktop-artifact.ts) uses Windows NSIS, a stable `com.t3tools.t3code` app ID, and a GitHub feed chosen through `T3CODE_DESKTOP_UPDATE_REPOSITORY`, then `GITHUB_REPOSITORY`, then its upstream default. A repository override changes destination, not access rights. A managed generic HTTPS feed can replace the baked GitHub feed. Its [release checklist](https://github.com/pingdotgg/t3code/blob/ea3e20a0e283ba3bf7c3d6004142d8f13b603319/docs/operations/release.md) publishes installers plus updater manifests/blockmaps after checks and describes Azure Windows signing. FreedomStream needs Velopack feed/package formats, not T3's `latest.yml` format.

## Proposed native path

1. Stage the already-qualified publisher, media DLL/plugins, app-local CRT, notices and corresponding library sources into a clean package directory. Use Velopack's per-user `Setup.exe`, which installs under `%LOCALAPPDATA%\{packId}` and provides shortcuts/uninstall integration. This is a new installed distribution contract; Phase 10's no-install portable contract remains separate. Avoid MSI unless enterprise deployment is needed. [Installers](https://docs.velopack.io/packaging/installer), [existing packaging](../../scripts/package-windows.mjs).
2. Initialize `VelopackApp::build().run()` first in the designated main executable; use Rust `UpdateManager`/`HttpSource`, with checking/download work off the GUI thread. Add explicit Download, Restart to update, Later and retry/error states. Stop media and persist only permitted settings before applying. The Rust SDK supports `wait_exit_then_apply_updates` for graceful cleanup; immediate apply/restart exits the process. [Rust quick start](https://docs.velopack.io/getting-started/rust), [Rust UpdateManager](https://docs.rs/velopack/1.2.161/velopack/struct.UpdateManager.html).
3. Build packages with a pinned `vpk` CLI and increasing SemVer, stable package ID and fixed main EXE name. The CLI requires a build-machine .NET SDK; this does not make a native Rust application require .NET on users' machines. Do not pass `--framework` for bundled CRT: that option downloads/installs shared prerequisites and violates offline/self-contained expectations. [Rust setup](https://docs.velopack.io/getting-started/rust), [prerequisite bootstrapping](https://docs.velopack.io/packaging/bootstrapping).
4. Publish full/delta `.nupkg` assets before atomically publishing `releases.{channel}.json`; retain a previous full package to generate deltas and support full-download fallback. Existing `publisher.json` is not a Velopack update feed. Keep the first channel simple and disallow accidental preview/downgrade offers. [Release assets/feed](https://docs.velopack.io/distributing/overview).

## Integration hazards that must be resolved

| Hazard | Evidence and required treatment |
| --- | --- |
| Portable cleanup kills updater | [Portable Windows runner](../../apps/portable/src/windows.rs) assigns the publisher at process creation to a job with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`; the wrapper waits, then closes that job. Velopack [apply code](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/src/lib-rust/src/manager.rs) starts Update.exe and waits for the app PID; its [Windows spawn](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/src/lib-rust/src/process_win.rs) uses `CREATE_NO_WINDOW`, without breakaway. Inference: calling it from the current publisher makes the updater inherit the job and exposes it to termination on publisher exit. Prefer a direct installed publisher/main launcher without this outer job, or an explicit wrapper-owned handoff outside the job. Preserve cleanup for capture helpers; do not broadly enable breakaway. |
| Bootstrap and runtime setup order | [Current publisher main](../../apps/publisher/src/main.rs) initializes DPI/diagnostics/GStreamer before argument dispatch. Velopack hooks must run before this work, UI, room restoration or media startup. Its startup integration belongs in the EXE named by `--mainExe`, exactly once; if that is a launcher, run before extraction/forwarding. Direct installation must preserve the portable runner's DLL/GStreamer path isolation and CRT selection; merely copying files and bypassing the wrapper is insufficient. [Startup contract](https://docs.velopack.io/integrating/overview), [runtime environment](../../apps/portable/src/lib.rs). |
| Stable identity through rebrand | Choose a permanent package ID/install root, main executable filename, AppUserModelID and update feed/channel. Change title/icon/resources independently. `--packTitle` also affects shortcut and portable-entry names, so review that change explicitly. Preserve or migrate `%LOCALAPPDATA%\FreedomStream\settings.json` without exposing its DPAPI invitation. Current payload-hash directories change the real publisher path every release; a fixed installed `current\<fixed-name>.exe` avoids that particular path churn, but does not prove firewall prompts disappear. [Installer options](https://docs.velopack.io/packaging/installer), [installed layout/AUMID](https://docs.velopack.io/integrating/overview), [saved settings](../../apps/publisher/src/settings.rs), [current behavior](../distribution.md). |
| Signing the portable overlay | [Bundle reader](../../apps/portable/src/lib.rs) requires its 56-byte footer at physical EOF; [packager](../../scripts/package-windows.mjs) appends ZIP/footer to the launcher. Inference: signing the final overlay appends Authenticode data after that footer and breaks this reader; appending payload after signing is not a valid signing strategy to assume. Fix/qualify signature-aware payload location or keep installer packaging independent. Sign inner binaries before packaging and generate download hashes only after final signing. |
| Signed delivery is more than checksums | Configure signing inside `vpk pack` so its own Setup/Update helpers and application binaries are signed at the proper stages (`--signParams`, signing template or supported Azure signing). A `.nupkg` checksum is not publisher authentication. Rust download code validates package size/hash from the feed; the inspected path does not establish pinned-publisher signature enforcement. Require trusted HTTPS/feed access and separately qualify signature verification/tamper rejection. Do not advertise that unsigned manifests or hashes alone secure update provenance. [Signing](https://docs.velopack.io/packaging/signing), [Rust verification source](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/src/lib-rust/src/manager.rs). |
| Restart arguments and mutable files | Velopack's Windows process helper logs launch arguments: never pass an invitation/session token as restart arguments. Reopen using existing DPAPI settings and keep tokens in memory. The installed `current` directory is replaced during updates: settings/logs/GStreamer registry cache belong outside it. Preserve the ability to replace LGPL libraries and inspect accompanying sources/notices. [Process logging](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/src/lib-rust/src/process_win.rs), [file layout](https://docs.velopack.io/integrating/overview), [portable guarantees](../distribution.md). |

## Blockers and acceptance

No repository-visibility or MIT-license blocker to implementation. Shipping needs a chosen public/authenticated feed and deployment credentials; a permanent identity/rebrand decision; a resolved updater lifetime/runtime-bootstrap architecture; and a code-signing identity/CI integration (unsigned local qualification can proceed). No signing credentials or deployment configuration were examined in this research.

Before claiming delivery works, test two real installed versions: offline initial launch without shared prerequisites; check/download/progress/Later/restart; helper survival after publisher exit; cleanup of all media before replacement; saved-room continuity without restarting capture/subscriptions; interrupted/corrupt downloads, concurrent instances and unavailable/auth-denied feeds; signed installer/helper/app verification and tamper rejection; uninstall and old portable coexistence. Inspect logs for secrets and observe console/firewall behavior on a fresh Windows machine. These are proposed checks, not completed results; existing hardware/media/deployment gates remain open.
