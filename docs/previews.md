# Private stream previews

An unwatched tile receives a JPEG, not a video track. Publishers generate one still when capture starts and no more than one every 60 seconds after that. Joining, Watch/Stop watching, HTTP retries and a media reconnect do not request a new capture. A late viewer receives the latest available image immediately.

Both publishers letterbox the source into 320×180, preserving aspect ratio, and encode baseline JPEG at quality 60. Uploads cannot exceed 64 KiB. Windows uses a bounded branch of the existing GPU capture pipeline: the minute gate runs before GPU scaling, downloading the small image, and JPEG encoding. Ordinary video stays on its hardware path. The browser baseline temporarily attaches its app-owned capture to an off-DOM muted video for one still, then releases that element; it does not acquire another device or keep a hidden video playing. Preview failure leaves a placeholder and does not request a lower-quality video subscription.

The server retains only the latest image for each publisher/source in RAM. Nothing is written to a file, SQLite, a public object store, or a shared CDN. Images expire after three minutes, including after a failed uploader; a sweep runs every 30 seconds. The process caps storage at 256 recent publisher/source entries (16 MiB of images at maximum size), with at most 16 upload jobs. Stop releases image bytes immediately; its small cadence descriptor remains until expiry so DELETE cannot reset the same track's minute limit. It reads bounded JPEG headers/scan structure to enforce dimensions and a single baseline image, without decoding or transcoding pixels. Restarting the app clears all preview images; publishers regenerate on their normal minute clock.

## Access and notifications

- POST `/api/rooms/:roomId/previews/:kind` sends `image/jpeg` plus `X-Track-Sid`. The authenticated cookie fixes the publisher identity. Exact Origin validation and the API rate limit apply. A privileged SFU lookup must confirm that identity's current, unmuted screen/camera track matches the SID.
- A successful upload announces a bounded descriptor in the publisher's `freedomstream.preview.screen` or `.camera` participant attribute. This uses a server-side administrative RPC, not participant data-publish permission. Independent attribute keys avoid read/modify/write races between camera and screen. The descriptor is a notification, never image access authority.
- GET `/api/rooms/:roomId/previews/:publisherId/:kind/:revision` requires an admitted same-room session and rechecks the active, unmuted SFU publication. Stopped, muted, replaced or expired publications return no image. Responses are private and `no-store`; clients use short-lived blob URLs and revoke them on replacement/unmount.
- DELETE of the publisher's kind includes its SID. Stop removes matching bytes/cancels an in-flight upload; an old Stop cannot erase a replacement stream. Leave/rejoin also purges that session's previews. A crash or failed DELETE is covered by the GET live-publication check and expiry. The room UI removes tiles as publications disappear.

Images and uploader work share no camera/microphone acquisition, RTC subscription, or server video decoder. Watching an incompatible HEVC stream remains disabled, but its JPEG can still identify it. A transient SFU outage denies preview access instead of serving unchecked cached content. Client retries reuse the same JPEG; new media SIDs reattach the cached image after full reconnect, preserving the capture clock.

The API's `LIVEKIT_INTERNAL_URL` is the administrative HTTP(S) origin reachable from the app container. It defaults to the public media WebSocket URL with the scheme converted; Compose explicitly uses `http://livekit:7880`. Only the server holds the administrative key/secret. The public media URL and browser Content Security Policy continue to use `LIVEKIT_URL`.
