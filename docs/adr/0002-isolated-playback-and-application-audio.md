# Mix approved applications and own the viewing process tree

Use positive WASAPI process-tree captures and mix approved applications instead of capturing the entire output endpoint and trying to remove Discord afterward. Windows provides one include/exclude process tree per loopback activation; independent captures allow several exclusions without signal subtraction or voice DSP. Keep the policy and Windows discovery private to the audio module. Unknown process identities and protected descendants fail closed.

Provide an isolated Chrome viewing window under a publisher-owned Windows job. A normal browser can mix room playback with unrelated tab audio in the same process; a dedicated profile/process tree gives capture policy an attributable exclusion and preserves the tested Chrome HEVC receive path. Chrome remains a separately installed browser, not a redistributed application dependency. Pass invitations through local control after launch, keep profiles temporary, and terminate the complete process job on leave/exit. A publisher using a regular browser must exclude it explicitly. This adds local browser lifecycle code in exchange for reliable playback attribution without a new audio driver, embedded proprietary runtime or privileged routing change.
